# WORKTREES, INTEGRATE, PREP, PROVENANCE REPAIR (publisher)

Commits use the `release-commit` identity rules. Refuse anything not listed here (no pushes, no config changes, no other branches or worktrees).

- **WORKTREES**: `git -C ORG_ROOT worktree add -b release/<VERSION>-docs .monomind/orgs/release/work/docs <sha>` (DOCS) and `... -b release/<VERSION>-fix-2 .monomind/orgs/release/work/fix-2 <sha>` (FIX2); `<sha>` = SRC HEAD unless the brief names another. Pin evidence to the new worktree's ABSOLUTE path and its HEAD.
- **INTEGRATE** (SRC has no tracked changes and no other role is editing it): bring the DOCS or FIX2 branch the brief names into SRC. DOCS while SRC HEAD is still its base: `git -C SRC merge --ff-only release/<VERSION>-docs`. Otherwise, and always for FIX2, cherry-pick the branch's own commits oldest first: `GIT_COMMITTER_NAME=nokhodian GIT_COMMITTER_EMAIL=nokhodian@gmail.com git -C SRC cherry-pick $(git -C SRC merge-base HEAD <branch>)..<branch>` (authorship kept; no -x, no trailers). Only commits of FIX tasks that COMPLETED: commits a cancelled FIX task left on a branch are never integrated (2.16.2: the fixer committed after its task was cancelled). On a conflict `git -C SRC cherry-pick --abort`, change nothing else, report the conflicting files and items. Report the new SRC HEAD, old to new SHA map, `git -C SRC cherry HEAD <branch>` (no `+` line) and `git -C SRC status --porcelain` (empty); evidence pinned to SRC (absolute path) and its new HEAD. Read the matching `fix-record` / `docs-record` for the commit list.
- **PREP** only when you have confirmed from the accepted records (`build-record`, `test-record`, `qa-*-record`) and `git log` that the round's checks passed AND docs-writer's commit is integrated into SRC (or its `docs-record` carries the evidenced "no docs needed"); otherwise refuse. In SRC: bump root and `packages/@monomind/cli` package.json to VERSION (leave `workspace:*` pins alone); bump the patch of each sub-package whose non-test source changed since the last release and nothing else (#636); move CHANGELOG `[Unreleased]` into `## [VERSION] — <date>` covering EVERY change in the range (breaking first, with replacements), each description matching its commit and citing SHAs that exist on the branch (the brief lists commits with their user-visible effect); run `npm run check:versions` and no other publish check (never check-published-pins or prepublishOnly: 2.16.2's PREP waited 8.6 of 10 minutes on it); commit `chore(release): publish VERSION`, no trailers. Then publish `prep-record`.
- **PROVENANCE REPAIR**: rebuild offending commits with identical trees, oldest first: `GIT_AUTHOR_NAME=nokhodian GIT_AUTHOR_EMAIL=nokhodian@gmail.com GIT_COMMITTER_NAME=nokhodian GIT_COMMITTER_EMAIL=nokhodian@gmail.com git commit-tree <old>^{tree} -p <new parent>` with the original message minus forbidden trailers (keep the author date), then `git update-ref refs/heads/release/<VERSION> <new head> <old head>`. Report the old to new map with tree equality. Remove a repo-local identity with `git -C ORG_ROOT config --local --unset-all user.name` (and user.email): the only permitted git config call.
