# PREFLIGHT and SETUP (publisher)

You run these because you alone have npm, GitHub and git credentials. Read-only except where SETUP says otherwise. Commands from ORG_ROOT with the core env prefix; never print a token (`npm token list` is forbidden).

## PREFLIGHT task
Run ALL groups, reply with a table (group, command, exit, PASS|WARN|MISSING, one line) and write it to `ORG_ROOT/.monomind/orgs/release/reports/preflight-<UTC ts>/PREFLIGHT.md`. The first line notes a task-named VERSION that differs (VERSION below).
1. TOOLS: `node --version` >= 20; pnpm, npm, git, gh, curl on PATH; `pnpm --version` works.
2. NPM: `npm ping`; `npm whoami` is nokhodian; publish-without-OTP: `npm profile get --json` with `tfa.mode` `auth-and-writes` and no granular token means every publish needs an OTP, MISSING. A 403 there is EXPECTED with a granular token (`grep -c '_authToken=npm_' ~/.npmrc` prints only a count): PASS with a WARNING. An npm notice that "tokens that bypass 2FA are being restricted" is a WARNING for PREFLIGHT.md and REPORT.md (future unattended publishing may need `npm stage approve` or trusted publishing). For monomind, @monoes/monomindcli and every sub-package that might be bumped, `npm access list collaborators <pkg> nokhodian --json` shows read-write.
3. GITHUB: `gh auth status` logged in with scopes including repo and workflow; `gh api repos/monoes/monomind --jq .permissions` push:true; `gh api repos/monoes/monomind/branches/main/protection` 404 (unprotected; record `expectExit 1`, "404 = branch not protected") or allows the owner to push; `gh api repos/monoes/monomind/rulesets` blocks no direct push or tag on main; `gh run list --workflow pages.yml --limit 1` works.
4. GIT: `git -C ORG_ROOT ls-remote origin HEAD`; `git -C ORG_ROOT push --dry-run origin origin/main:refs/heads/main` (proves push auth, pushes nothing); `git config --global --get user.name` / `user.email` are nokhodian / nokhodian@gmail.com; `git -C ORG_ROOT config --local --get user.name` prints nothing (`expectExit 1`, "unset = no repo-local identity").
5. LOCAL STATE: ORG_ROOT is on `main` with no tracked changes (`symbolic-ref --short HEAD`, `status --porcelain --untracked-files=no`; otherwise only a WARNING: LOCAL MAIN SYNC needs it); the target (the brief names a branch, tag, SHA or worktree path; none = local `main`; uncommitted work is not included) resolves to a SHA; no other `org run release` process for this clone is running (`ps -eo pid,args | grep '[o]rg run release'`; this run's own does not count).
6. AGENT TRIALS: `claude auth status` loggedIn:true; then `MONOMIND_NO_AUTO_INSTALL=1 monomind agent models --runtime claude --json` (with the env prefix): exit 0, `supported: true`, nonempty `models`, no `error`. It loads the pinned SDK and starts its Claude executable, sends no prompt, installs nothing; a package directory existing proves nothing (#592). Failure: MISSING with the exact error and remedy `monomind deps install`, which the operator runs outside any org role; org roles never install into the read-only dependency cache or clear role markers. No SETUP and no live Claude trial (RUNTIME QA's `none`, `stdio` and timeout checks stay mandatory, never SKIP) before this passes.
7. RESOURCES: free disk on /home >= 20 GB; `df /tmp` use < 50%; `$HOME/mrg-tmp` and `$HOME/monomind-release` writable. No Chromium (`which chromium google-chrome`) is only a WARNING (browse smoke becomes SKIP).
8. VERSION: resolve it as below and record it.
Anything MISSING in 1-4, 6, or insufficient disk/tmp: say so plainly in the result; the captain asks the human. Never push, change config or touch SRC.

## SETUP task
- TAG CHAIN: `git -C ORG_ROOT fetch origin --tags`. `<previous>` = version X of the last `chore(release): publish X` commit C reachable from the target (`git -C ORG_ROOT log -1 --format='%H %s' --grep='^chore(release): publish ' <target>`); every `v<previous>` range this run means C. Check `git -C ORG_ROOT rev-parse -q --verify 'refs/tags/vX^{commit}'` equals C and `curl -s https://api.github.com/repos/monoes/monomind/releases/tags/vX` has tag_name vX (2.18.3 shipped to npm and main with neither, #386).
  - both present: nothing. One missing and `npm view monomind@X version` prints X: WARNING, then TAG HEAL on the spot: `GIT_AUTHOR_NAME=nokhodian GIT_AUTHOR_EMAIL=nokhodian@gmail.com GIT_COMMITTER_NAME=nokhodian GIT_COMMITTER_EMAIL=nokhodian@gmail.com git -C ORG_ROOT tag -a vX -m 'monomind X' C` + `git -C ORG_ROOT push origin vX` (only the missing steps), then write C's `## [X]` CHANGELOG.md section plus an `**npm**:` line to `$GATE/release-notes-X.md` and `gh release create vX --verify-tag --latest=false --title vX --notes-file $GATE/release-notes-X.md` (never `--latest`). `vX` pointing elsewhere, or X not on npm: WARNING only, change no tag or release, use C.
- VERSION (no human input): base is the last `chore(release): publish X`; any commit since with a `type(scope)!:` subject or a `BREAKING CHANGE:` footer means next MINOR, else next PATCH. It must be above both ORG_ROOT's package.json version and `npm view @monoes/monomindcli version`. A task-named version is used only if it is above both (deliberate minor/major); otherwise release the next free one and note `VERSION: task named X, npm already has Y, releasing Z`.
- GATE: `mkdir -p $GATE/npm-cache $GATE/logs $HOME/mrg-tmp` with GATE = `$HOME/monomind-release/<VERSION>-<UTC ts>`.
- WORKSPACE: if SRC exists on branch `release/<VERSION>` (interrupted run) reuse it: it must descend from the target with no tracked changes, and every commit since the target is re-verified, not trusted. Else `git -C ORG_ROOT worktree add -b release/<VERSION> .monomind/orgs/release/work/src <sha>` and confirm `git -C SRC rev-parse HEAD`.
- HYGIENE, narrow: leave every other run's GATE under `$HOME/monomind-release` alone whatever its age (this run's is pruned at CLEAN UP; 2.16.14 deleted the logs issues #351/#352 cited); delete `.monomind/orgs/release/work/*.log`; in `$HOME/mrg-tmp` prune only immediate subdirectories named `<check>-<short-sha>` or `home-<short-sha>` of an EARLIER run (short-sha is not this target, mtime before this run's start), never the root, never an unattributable entry (#273); close stale pending items (`monomind org questions release`, `monomind org approvals release`; answer each "stale: from a previous run", #248); delete local `release/*` branches contained in origin/main (`git branch --merged origin/main --list "release/*"`).
- Reply: VERSION, TARGET SHA, `<previous>` and C, GATE, SRC, warnings. Evidence pins to SRC (absolute path) and its HEAD.
